# Claude 連携（案件管理アプリ ⇔ 仮想カンパニー）

アプリに入れた案件・納期・単価・請求・入金を Claude（`E:\個人フォルダ\.company` の秘書・各部署）が読み、
秘書が記録した進行（段階・進行メモ・納期・新しい案件）をアプリに書き戻す。オーナーが同じことを二度書かないため（0.16.0〜）。
0.18.0 からは、アプリの画面でできる操作（完了・削除・請求書の発行と入金・請求書の PDF・単価タブ・委託先・請求書の設定・書き出しと読み込み）をすべて Claude からもできる（下の対応表）。

## 仕組み

```
アプリ（PC・スマホ）──同期──▶ Google ドライブ（アプリ専用の見えない場所）… いままでどおりの同期
   │  同期のたびに（Claude 連携がオンの端末）
   ├─書く──▶ マイドライブ/案件管理（Claude連携）/anken-kanri.json   … 写し（アプリだけが書く）
   └─読む──◀ マイドライブ/案件管理（Claude連携）/claude-inbox.json  … 受け箱（Claude だけが書く）
                         ▲▼  Google ドライブ（PC 版）で G:\マイドライブ に見える
          tools/claude-link/anken.py（Claude が使う）
```

- 1 つのファイルを書くのは 1 か所だけ（写し＝アプリ、受け箱＝Claude）なので、同時に書いてもファイルが壊れたり消し合ったりしない
- Claude の変更は「パッチ」（どの案件の・どの項目を・前の値 → 新しい値）。アプリは同期のたびに受け箱を読み、項目ごとに当てる
  - いまの値が「前の値」のまま → 当てる
  - いまの値がもう「新しい値」→ 何もしない（別の端末で当て済み）
  - どちらでもない（アプリでも変えた）→ **後から変えた方を残す（同じ時刻ならアプリ）**。残さなかった方は「競合」として記録
  - 別の項目の変更は両方残る（例: アプリでメモ、Claude で進行メモ）
- 当てた結果は写しの `claude.results` と、アプリの設定画面「Claude 連携」のログに出る。取り込み済みのパッチは、Claude が次に受け箱を書く時に消す
- アプリで当てた変更は普段の同期で全端末に広がる。案件の `changedBy` に「秘書」などが入り、一覧の進行メモを押さえると「（秘書が更新）」と出る
- 受け箱のファイルを作るのはアプリだけ（アプリの権限は「自分が作ったファイルだけ」なので、Claude が作ったファイルは読めない）。Claude 側は中身だけを書き換える（ファイルを置き換えない）

## はじめに（端末ごとに 1 回）

1. アプリの歯車 → 設定 →「Claude 連携」の「この端末で Claude と連携する」をオン
2. Google のログイン画面が出るので、同じアカウントで許可する（「このアプリが作ったファイルだけを扱う」権限が増える）
3. 同期が終わると、マイドライブに「案件管理（Claude連携）」フォルダができる。設定画面に「連携しています（最後に写しを書いた 時:分）」と出れば OK
- 写しはアプリを開いて同期した時に新しくなる（開いている間は 5 分ごと）。PC で常に開いておく必要はない。Claude の変更も、アプリを次に開いた時に入る
- ログインは約 1 時間で切れる（いままでどおり）。切れたらヘッダーの同期ボタンを押す

## Claude から同期（アプリを開かなくても）

`node tools/claude-link/drive-sync.cjs sync`（anken.py の `sync`、`company` も先にこれを回す）で、アプリの同期 1 回分を Claude がする。
アプリのデータ（appDataFolder）を読み → 受け箱（G:\ の claude-inbox.json）を当て → 変わっていれば書き戻し → 写しを書く。当て方はアプリの `applyClaudePatches`・`claudeExchange` をそのまま使う。
ほかの端末は、いままでどおり次の同期で取り込む。写しはドライブ（PC 版）が G:\ に届けるまで少しかかるので、その間 anken.py は控え（`.company/.anken/mirror-cache.json`）を読む。

### はじめに（PC で 1 回）
1. Google Cloud コンソールで、アプリのクライアント ID（js/config.js）がある **同じプロジェクト** を開く → API とサービス → 認証情報 → 認証情報を作成 → OAuth クライアント ID → 種類「デスクトップ アプリ」で作る → JSON をダウンロード
2. その JSON を `%APPDATA%\anken-kanri-claude\client.json` に置く（リポジトリには入れない）
3. `node tools/claude-link/drive-sync.cjs login` → ブラウザで同じアカウントでログインして許可（チェックは全部）→ 「ログインしました」
- OAuth 同意画面の公開ステータスが「テスト」のままだと、7 日でログインが切れる（`login` をやり直す）。使う権限は drive.appdata・drive.file だけ
- 別のプロジェクトのクライアントだと、アプリのデータも連携フォルダも見えない（403・404・「アプリのデータがドライブにありません」）

## Claude 側（anken.py）

Python 3.10 以上、標準ライブラリだけ。`python "E:\個人フォルダ\案件管理\tools\claude-link\anken.py" <コマンド>`（`<コマンド> -h` で使える指定の一覧）

- `<案件>` は id の先頭 6 文字以上か、案件名・クライアント名の一部。`<月>` は `2026-10` の形（省くと今月）。日付は `2026-11-19`・`11/19`・`今日`・`なし`
- 書き込むコマンドは、アプリの次の同期で取り込まれる（結果は `status`）。見るコマンドは、取り込み待ちの変更も重ねて出す（※アプリ取り込み待ち）
- `add`・`set`（今までの項目）と `done`・`undone` 以外の書き込みは、アプリ **0.18.0 以降** が書いた写しの時だけ受け箱に書く（古い版は知らない操作を捨ててしまうので、止めて知らせる）

### 例

```
# 2026-10 のクライアントAを、請求書発行済み・入金済みにする（日付はオーナーに聞く）
python anken.py bill 2026-10 クライアントA                                  # 今の状態
python anken.py bill 2026-10 クライアントA --invoiced 2026-10-31 --paid 2026-11-10
python anken.py status                                                # アプリが取り込んだか

# 月末の請求書を PDF と CSV で作る（発行済みになり、控えが残る）
python anken.py invoice 2026-11 クライアントA --pdf --csv

# 案件を消して、戻す
python anken.py delete 1120_テスト
python anken.py restore 1120_テスト
```

### そろえ方（.company）

| コマンド | すること |
|---|---|
| `link <jobファイル> <案件>` | `.company/clients/<クライアント>/<シリーズ>/<日付_内容>/進行.md`（2026-11-25 から。前の `.company/production/jobs/*.md` も読む）に `anken_id` を入れて結び付ける。場所は `.company` から見た場所でよい |
| `company [--dry-run]` | 結び付いた jobs とアプリを両方向にそろえ、`.company/secretary/anken-app.md`（進行中の納期・請求月ごとの金額と請求・入金の状態・単価）を作り直す |

- 書く前に、写し・受け箱・書き換える jobs を `.company/.anken/backup/<日時>/` に必ずコピーする（60 回分残す）。書いた内容は `.company/.anken/log.txt`
- `company` のそろえ方（jobs の front matter ⇔ アプリ）: `due` ⇔ 納期、`stage` ⇔ 段階（作業中／初稿提出／修正中／完了）、`status` ⇔ 進行メモ。前回そろえた値（`.company/.anken/state.json`）と比べ、片方だけ変わっていればそれを反映、両方変わっていれば後から変えた方（jobs はファイルの更新時刻、アプリは案件の更新時刻）、同じならアプリ
- どこが正か: 単価・請求・入金・完了はアプリ。細かい進行（チェックリスト・判断）は `.company`

### 提出した動画（0.19.0）

| コマンド | すること |
|---|---|
| `deliveries [--dry-run] [--all]` | 提出フォルダの動画を、案件名と合わせて案件の `deliveries` に入れる（進行中と、完了から 60 日以内。`--all` で全部）。`company` でも毎回する |

- 見るフォルダは `.company/.anken/deliveries.json` の `roots`（クライアント → フォルダの一覧、下のフォルダも全部見る）。初めて出たクライアントは `E:\<クライアント>\提出` があれば入る（別の場所に置いているクライアントは手で書く）。`skipDirs` の名前のフォルダ（frameio・サムネイル・test など）は見ない。手で直してよい
- 合わせ方: 同じクライアントの案件で、ファイル名か入っているフォルダ名を「【初稿】などの印・日付の頭（`1119_`）・コピー_・記号と空白」を取った形にして、案件名と片方がもう片方に入っていれば合う（3 文字以上）。日付は着手の 3 日前〜完了の 14 日後（進行中は今日の 14 日後）。2 件に同じくらい合う動画は入れずに知らせる
- 1 本の中身: `path`・`name`・`label`（【初稿】→ 初稿、【修正版】→ 修正版、【横動画】→ 横動画、フォルダ名で合った物はファイル名、印が無ければ「提出」）・`size`（バイト）・`at`（ファイルの更新日時 `YYYY-MM-DDTHH:MM`）。古い順に 12 本まで
- アプリでは見るだけ（一覧の「▶ 提出 …」と入力画面の「提出した動画」。押すとパスをコピー）。写しが 0.19.0 より前なら受け箱に書かない

### 受け箱の操作（パッチ）

| op | 中身 | アプリの当て方 |
|---|---|---|
| `add` | `project` | 同じ id が無ければ足す（ゴミ箱にある id は足さない） |
| `update` | `projectId`・`before`・`after` | 項目ごとに 3 方向（上の「仕組み」） |
| `delete` | `projectId`・`seen`（Claude が見た `updatedAt`） | ゴミ箱へ（中身を残す）。Claude が見た後にアプリで変えていたら消さない（競合） |
| `restore` | `projectId`・`project` | ゴミ箱の中身（無ければ `project`）を今の時刻で戻す |
| `invoice` | `key`（`YYYY-MM\|クライアント`）・`before`・`after`（`invoicedAt`・`paidAt`・`snapshot`） | 項目ごとに 3 方向（請求の記録の `updatedAt` と比べる） |
| `settings` | `changes: [{path, before, after \| remove}]` | 場所（例 `["clientPrices","クライアントA","short"]`）ごとに 3 方向。別の場所の変更は両方残る。`clientIcons` は変えない |
| `import` | `data`（`projects`・`invoices`・`settings`） | 読み込みと同じ置き換え。消える案件はゴミ箱へ |

## 元に戻すとき

- 消した案件（アプリでも Claude でも）: 設定画面の「ゴミ箱」で「戻す」、または `anken.py restore <案件>`（0.18.0 から。それより前に消した案件は中身が残っていない）
- Claude の書き戻しが変だった: `.company/.anken/backup/<日時>/anken-kanri.json` が書く前のアプリのデータ（写し）。このファイルをそのままアプリの「読み込み」で入れると、その時の状態に戻せる（読み込みは今のデータを置き換えるので、先に「書き出し」で今のデータを保存しておく）
- 連携をやめる: 設定画面でオフ。フォルダは残るので、要らなければドライブで消す

## テスト

`python tools/claude-link/test_link.py` … 一時フォルダで、Claude 側（anken.py）とアプリ側（`fake-app.cjs` が本物の `js/claude-link.js` のパッチの当て方を使う）を交互に動かし、取り込み・競合（アプリが後／Claude が後）・別の項目・二重追加・.company とのそろえ方に加え、0.18.0 の操作（完了・戻す・単価や追加料金・請求と入金・ゴミ箱・単価タブ・委託先・請求書の設定・請求書の CSV／HTML／PDF・書き出しと読み込み・古いアプリの時は止める）と、0.19.0 の提出した動画（合わせ方・frameio や古い物を入れない・変わらなければ書かない・company でも入る）を確かめる（61 項目）。Google ドライブは使わない。
